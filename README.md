## 🔍 What Is Ocprobe?

Enterprise-grade model catalog probe for [OpenCode](https://opencode.ai). It handles the full lifecycle: catalog diffing, live probing, alerting, safe application and continuous monitoring. Full docs and features: [oc-model-manager](https://github.com/SunnyJayaRaju/oc-model-manager).

<details>
<summary><b>What Changed in 3.2.x</b></summary>

- **OpenCode 2.x support** — generation is detected at runtime: config discovery (`opencode.jsonc` preferred), session work through the 2.x tables, backup and restore via `opencode session export`/`import`, and guarded session cleanup against the 2.x tables.
- **Safer applies** — on OpenCode 2.x, `validate --apply` refuses to write per-provider model lists (2.x does not honour them); 1.x behaviour is unchanged.
- **Session hygiene** — every probe run now cleans up its own probe session, and session queries bind their parameters.

Full list: [CHANGELOG](https://github.com/SunnyJayaRaju/oc-model-manager/blob/main/CHANGELOG.md).

</details>


## 🛠️ Troubleshooting

- **A message about `python3` lacking PyYAML or jsonschema**: this applies to manual or source installs only. The tap formula builds a dedicated Python virtualenv during install (including PyYAML and jsonschema), so `brew install` needs no extra steps. If you installed from source instead, follow the hint that `ocprobe doctor` prints.
- **Stale version after a release**: run `brew update` first. The formula is regenerated by CI in the main repo when a release ships, so Homebrew only sees it after an update.

## 🔄 How This Tap Stays Current

`Formula/ocprobe.rb` is updated automatically by CI in the main [oc-model-manager](https://github.com/SunnyJayaRaju/oc-model-manager) repo whenever a new release ships. This tap is not manually maintained; it always reflects the latest release.
